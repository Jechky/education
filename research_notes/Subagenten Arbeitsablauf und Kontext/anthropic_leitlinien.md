# Anthropic's official guidance on Claude Code subagents, context management and multi-agent orchestration (for a "coordinator-only" main agent setup)

Research date: 2026-10-02. Sources are Anthropic's live Claude Code docs (code.claude.com, current as of Claude Code v2.1.28x) and Anthropic Engineering blog posts from 2025. Some legacy URLs now redirect: `https://www.anthropic.com/engineering/claude-code-best-practices` returns **308 Permanent Redirect → https://code.claude.com/docs/en/best-practices**, so the original April 2025 blog post has been replaced by the docs page. Quotes from code.claude.com pages (best-practices, memory, costs, agent-teams) were retrieved as raw page markdown and are verbatim. Quotes from the sub-agents page and the engineering blog posts came through a summarizing fetch tool. They are very likely verbatim, but treat them as close quotes (see Gaps).

Legend: **[OFFICIAL]** = a stated recommendation or documented behavior. **[EXAMPLE]** = an illustrative example, an internal case study or a number from one specific system.

## 1. Claude Code subagents: how they work, their context, what they return, when to use them, custom agent files, scope, parallelism limits

### Takeaway
Anthropic describes a Claude Code subagent as an isolated worker. It has its own context window, system prompt, tools and permissions, and it returns only its final summary to the caller. Anthropic recommends subagents for **self-contained, verbose or parallelizable side tasks**. It explicitly advises keeping work in the main conversation when phases share a lot of context, need iteration, or are latency-sensitive. That cuts against a "delegate absolutely everything" design.

### Cited Findings

**What a subagent is / isolation / what returns**
- [OFFICIAL] "Subagents are specialized AI assistants that handle specific types of tasks. Use one when a side task would flood your main conversation with search results, logs, or file contents you won't reference again: the subagent does that work in its own context and returns only the summary." — [Claude Code docs: Subagents](https://code.claude.com/docs/en/sub-agents)
- [OFFICIAL] "Each subagent runs in its own context window with a custom system prompt, specific tool access, and independent permissions." — [Subagents](https://code.claude.com/docs/en/sub-agents)
- [OFFICIAL] Subagents also cost usage: a subagent "sends its own requests, which count toward the same usage limits as your main conversation." — [Subagents](https://code.claude.com/docs/en/sub-agents)
- [OFFICIAL] What a non-fork subagent receives at startup: its own system prompt (not the Claude Code system prompt) plus environment details; a **"Task message: the delegation prompt Claude writes when it hands off the work"**; all CLAUDE.md levels (the built-in Explore and Plan agents skip these, and `omitClaudeMd` removes them); a git status snapshot; preloaded skills from the `skills` field; and a "sibling roster" of named agents it can message. — [Subagents: What loads at startup](https://code.claude.com/docs/en/sub-agents)
- [OFFICIAL] What a subagent does **not** receive: the parent conversation history, the output style, or the main conversation's auto memory. Also, "a subagent's context window is sized by its own model, not the parent's." — [Subagents](https://code.claude.com/docs/en/sub-agents); [Memory docs](https://code.claude.com/docs/en/memory) ("The main conversation's auto memory isn't loaded into subagents; the exception is a fork…")
- [EXAMPLE] The interactive context-window walkthrough shows a research subagent that reads 6,100 tokens of files while the main context receives a 420-token result: "Only the subagent's final text response comes back to your context, plus a small metadata trailer with token counts and duration… That's the context savings." The subagent's own setup in that example costs about 900 tokens of system prompt, about 1,800 tokens of CLAUDE.md copy, about 970 tokens of MCP tools and skills, and about 120 tokens of task prompt. — [Explore the context window](https://code.claude.com/docs/en/context-window)
- [OFFICIAL] **Forks**: "A fork is a subagent that inherits the entire conversation so far instead of starting fresh… The fork's own tool calls still stay out of your conversation and only its final result comes back… Use a fork when any other subagent would need too much background to be useful, or when you want to try several approaches in parallel from the same starting point." Forks share the parent's prompt cache, which "makes forking cheaper than spawning a fresh subagent for tasks that need the same context." Start one with `/subtask …`. — [Subagents: Fork the current conversation](https://code.claude.com/docs/en/sub-agents)

**When to use / not use subagents**
- [OFFICIAL] Use the **main conversation** when: "The task needs frequent back-and-forth or iterative refinement"; "Multiple phases share significant context, such as planning, implementation, and testing"; "You're making a quick, targeted change"; "Latency matters. A subagent that isn't a fork starts fresh and may need time to gather context". — [Subagents](https://code.claude.com/docs/en/sub-agents)
- [OFFICIAL] Use **subagents** when: "The task produces verbose output you don't need in your main context"; "You want to enforce specific tool restrictions or permissions"; "The work is self-contained and can return a summary". — [Subagents](https://code.claude.com/docs/en/sub-agents)
- [OFFICIAL] "Since context is your fundamental constraint, use subagents to keep research out of it… Subagents run in separate context windows and report back summaries." Example prompt: "Use subagents to investigate how our authentication system handles token refresh…" — [Best practices](https://code.claude.com/docs/en/best-practices)
- [OFFICIAL] Use subagents for adversarial review: "Before treating a task as done, have a subagent review the diff in a fresh context and report gaps… A reviewer running in a fresh subagent context sees only the diff and the criteria you give it, not the reasoning that produced the change." Caveat: "A reviewer prompted to find gaps will usually report some, even when the work is sound… Tell the reviewer to flag only gaps that affect correctness or the stated requirements." — [Best practices](https://code.claude.com/docs/en/best-practices)
- [OFFICIAL] Documented subagent patterns: (1) "Isolate high-volume operations" (tests, docs fetching, log processing); (2) "Run parallel research"; (3) "Chain subagents": "Each subagent completes its task and returns results to Claude, which then passes relevant context to the next subagent." — [Subagents](https://code.claude.com/docs/en/sub-agents)
- [OFFICIAL] Warning on parallel research: "Running many subagents that each return detailed results can consume significant context, and each subagent spends tokens of its own while it runs." — [Subagents](https://code.claude.com/docs/en/sub-agents)

**Built-in subagents**
- [OFFICIAL] **Explore**: read-only (Write/Edit denied), used for "file discovery, code search, codebase exploration", with thoroughness levels quick, medium or very thorough. **Plan**: read-only research used in plan mode. **General-purpose**: all tools, used for "complex research, multi-step operations, code modifications"; Claude delegates to it "when the task requires both exploration and modification, complex reasoning to interpret results, or multiple dependent steps." Explore and Plan are one-shot and cannot be resumed. — [Subagents: Built-in subagents](https://code.claude.com/docs/en/sub-agents)

**Custom agents in `.claude/agents/*.md`**
- [OFFICIAL] A custom agent file is Markdown with YAML frontmatter. The body is the system prompt. Required fields are `name` and `description`. Optional fields: `tools` (inherits all if omitted), `disallowedTools`, `model` (`sonnet`, `opus`, `haiku`, `fable`, a full model ID, or `inherit`; default is the main conversation's model), `permissionMode`, `maxTurns`, `skills` (preloaded full content), `mcpServers`, `hooks` (PreToolUse/PostToolUse/Stop scoped to the agent), `memory` (`user`/`project`/`local` persistent memory), `background`, `omitClaudeMd`, `effort`, `isolation: worktree`, `initialPrompt`, `color`, `experimental`. — [Subagents](https://code.claude.com/docs/en/sub-agents)
- [OFFICIAL] Scope priority when names collide: managed settings (1), `--agents` CLI flag (2), `.claude/agents/` project (3), `~/.claude/agents/` user (4), plugin `agents/` (5). — [Subagents: Choose the subagent scope](https://code.claude.com/docs/en/sub-agents)
- [OFFICIAL] Descriptions cost context: "Write a clear description so Claude knows when to use it. Those descriptions take up context, so keep them short." When combined custom descriptions exceed **15,000 tokens**, Claude Code warns at startup. Move detail "into each subagent's system prompt, which only loads when that subagent runs." — [Subagents](https://code.claude.com/docs/en/sub-agents)
- [EXAMPLE] Example agent from the best-practices page: `security-reviewer` with `tools: Read, Grep, Glob, Bash`, `model: opus`, and a short role prompt. Recommended invocation: *"Use a subagent to review this code for security issues."* — [Best practices](https://code.claude.com/docs/en/best-practices)
- [OFFICIAL] Preload skills via `skills` so the subagent has domain knowledge "without requiring it to discover and load skills during execution". Enable `memory` and "Ask the subagent to consult its memory before starting work… update its memory after completing a task". Use `PreToolUse` hooks for conditional tool rules. — [Subagents](https://code.claude.com/docs/en/sub-agents)

**Nesting, parallelism, background, resume, compaction**
- [OFFICIAL] Nesting (current behavior): "By default, a subagent can spawn subagents of its own, up to three layers below the main conversation." This is configurable via `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` (`1` disables nesting). To stop a specific agent from spawning, omit `Agent` from its tools or add it to `disallowedTools`. — [Subagents](https://code.claude.com/docs/en/sub-agents)
- [OFFICIAL] Concurrency cap: "By default, when 20 subagents are running in a session, spawning another with the Agent tool fails with `Concurrent subagent limit reached`". This is configurable via `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`; the docs note sessions with "ultracode" active are exempt. — [Subagents](https://code.claude.com/docs/en/sub-agents)
- [OFFICIAL] Foreground subagents block the main conversation. Background subagents (the default in interactive mode unless Claude needs the result before continuing) run concurrently, and their permission prompts surface in the main session. — [Subagents](https://code.claude.com/docs/en/sub-agents)
- [OFFICIAL] Resume: "Each subagent invocation creates a new instance rather than continuing an earlier one… Resumed subagents retain their full conversation history." Claude resumes a subagent via `SendMessage` with its ID or name. — [Subagents](https://code.claude.com/docs/en/sub-agents)
- [OFFICIAL] "Subagents support automatic compaction using the same logic as the main conversation." Transcripts persist at `~/.claude/projects/{project}/{sessionId}/subagents/agent-{agentId}.jsonl` and are deleted after `cleanupPeriodDays` (30 days by default). — [Subagents](https://code.claude.com/docs/en/sub-agents)
- [OFFICIAL] Cost control: route subagents to cheaper models (`model: haiku`), or force all subagents onto one model via `CLAUDE_CODE_SUBAGENT_MODEL` + `CLAUDE_CODE_SUBAGENT_MODEL_FORCE`. — [Subagents](https://code.claude.com/docs/en/sub-agents); [Model config](https://code.claude.com/docs/en/model-config)
- [OFFICIAL] `/batch <instruction>` "split[s] the change across 5 to 30 subagents. Each subagent works in its own worktree." — [Best practices](https://code.claude.com/docs/en/best-practices)

**Agent teams (alternative to subagents)**
- [OFFICIAL] Agent teams are **experimental and disabled by default** (`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`). In a team, "One session acts as the team lead, coordinating work, assigning tasks, and synthesizing results. Teammates work independently, each in its own context window, and communicate directly with each other." — [Agent teams](https://code.claude.com/docs/en/agent-teams)
- [OFFICIAL] Comparison table. Subagents: "Main agent manages all work"; best for "Focused tasks where only the result matters"; token cost "Lower: results summarized back to main context". Agent teams: "Self-coordination through messages, plus a shared task list"; best for "Complex work requiring discussion and collaboration"; token cost "Higher: each teammate is a separate Claude instance". — [Agent teams](https://code.claude.com/docs/en/agent-teams)
- [OFFICIAL] "Before you set up a team, check whether a lighter option does the job." Also: "For sequential tasks, same-file edits, or work with many dependencies, a single session or subagents are more effective." — [Agent teams](https://code.claude.com/docs/en/agent-teams)
- [OFFICIAL] Known issue for coordinator setups: "Sometimes the lead starts implementing tasks itself instead of waiting for teammates." Suggested prompt: "Wait for your teammates to complete their tasks before proceeding". Teams have "No nested teams: teammates cannot spawn their own teammates." — [Agent teams](https://code.claude.com/docs/en/agent-teams)

### Inferences
- A main agent that only coordinates matches the documented subagent model ("Main agent manages all work"; results summarized back). Still, the docs list cases where delegation is the wrong choice: iterative work, phases that share context, quick changes, and latency-sensitive work. Anthropic's guidance supports **selective** delegation (research, verbose operations, review, parallel independent work), not delegation of every task by default.
- Because a non-fork subagent starts without conversation history, the delegation prompt (the "Task message") is the only task-specific context it gets. A coordinator-only design therefore depends on high-quality, self-contained task briefs. Forks are the documented escape hatch when a brief would need too much background.
- The 20-concurrent and 3-level-depth limits are hard ceilings, not recommendations. The recommended practical numbers come from the agent-teams page (3–5) and the research blog (3–5 in parallel); see section 4.

### Gaps
- I did not find an official per-subagent token or turn budget recommendation for Claude Code (beyond `maxTurns` existing as a field).
- Older (2025) Claude Code docs reportedly said subagents could not spawn subagents. The current page allows 3 levels. I could not retrieve the historical version to cite the change date.
- The sub-agents page content came through a summarizing fetch; frontmatter field names should be double-checked against the live page before they are quoted as exact syntax.

## 2. Claude Code context: window size, auto-compaction, /compact, /clear, CLAUDE.md best practices, memory, context editing, token tips

### Takeaway
Anthropic treats the context window as "the most important resource to manage". Its main recommendations: `/clear` between unrelated tasks; `/compact <focus>` (or a lower auto-compact window) when continuity matters; CLAUDE.md under about 200 lines, with only broadly applicable rules; move specialized material to skills or path-scoped rules; offload verbose work to subagents and hooks. Current models run with a 1M-token window, with auto-compaction near about 967K by default. Older or non-extended models run at 200K.

### Cited Findings

**Context as the core constraint**
- [OFFICIAL] "Most best practices are based on one constraint: Claude's context window fills up fast, and performance degrades as it fills… When the context window is getting full, Claude may start 'forgetting' earlier instructions or making more mistakes. The context window is the most important resource to manage." — [Best practices](https://code.claude.com/docs/en/best-practices)
- [OFFICIAL] "A single debugging session or codebase exploration might generate and consume tens of thousands of tokens." — [Best practices](https://code.claude.com/docs/en/best-practices)

**Context window size and auto-compaction thresholds**
- [OFFICIAL] "Fable models, Sonnet 5 and later, Opus 4.6 and later, and Sonnet 4.6 support a 1 million token context window… Compaction works the same way at the larger limit." Sonnet 5.5/5 run 1M natively with no `[1m]` variant. — [Context window](https://code.claude.com/docs/en/context-window)
- [OFFICIAL] Default auto-compact thresholds: about **967K tokens** for native-1M models (Sonnet 5, Fable, Opus 4.7+); **200K** for Sonnet 4.6/Opus 4.6 without extended context, and for Opus 4.8+ on Bedrock/Agent Platform/Foundry; other models compact at the context limit. `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` makes 1M models compact at 200K. — [Model config](https://code.claude.com/docs/en/model-config)
- [OFFICIAL] The threshold is adjustable via `/autocompact 500k`, `--autocompact`, the `autoCompactWindow` setting, or `CLAUDE_CODE_AUTO_COMPACT_WINDOW` (range 100K–1M). — [Model config](https://code.claude.com/docs/en/model-config). `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` also applies to subagents — [Subagents](https://code.claude.com/docs/en/sub-agents)
- [OFFICIAL] "Compact earlier: run `/autocompact` with a token count, like `/autocompact 500k`, to set how full the context window gets before the automatic pass runs." — [Context window](https://code.claude.com/docs/en/context-window)

**/clear vs /compact**
- [OFFICIAL] "Use `/clear` frequently between tasks to reset the context window entirely." Also: "When auto compaction triggers, Claude summarizes what matters most, including code patterns, file states, and key decisions". And: "For more control, run `/compact <instructions>`, like `/compact Focus on the API changes`". — [Best practices](https://code.claude.com/docs/en/best-practices)
- [OFFICIAL] Custom compaction instructions can live in CLAUDE.md: "When compacting, always preserve the full list of modified files and any test commands". — [Best practices](https://code.claude.com/docs/en/best-practices); a similar "# Compact instructions" example appears in [Costs](https://code.claude.com/docs/en/costs)
- [OFFICIAL] Partial compaction: `/rewind` → "Summarize from here" / "Summarize up to here". — [Best practices](https://code.claude.com/docs/en/best-practices)
- [OFFICIAL] Cost of each: "`/compact` reads the conversation it summarizes, so compacting a large context is itself a large request. When you want a fresh start instead of continuity, `/clear` costs nothing". — [Costs](https://code.claude.com/docs/en/costs)
- [OFFICIAL] What survives compaction: system prompt; project-root CLAUDE.md and unscoped rules (re-injected from disk); auto memory (re-injected); the plan-mode plan (re-injected from disk); up to five most recently modified read or edited files (re-read); invoked skill bodies (capped at 5,000 tokens each and 25,000 total); background subagents keep running. Path-scoped rules and nested CLAUDE.md files reload when matching files are read. The skill-descriptions listing is *not* re-injected. — [Context window: What survives compaction](https://code.claude.com/docs/en/context-window)
- [OFFICIAL] "If an instruction disappeared after compaction, it was given only in conversation… Add conversation-only instructions to CLAUDE.md to make them persist." — [Memory](https://code.claude.com/docs/en/memory)

**CLAUDE.md best practices**
- [OFFICIAL] "CLAUDE.md is loaded every session, so only include things that apply broadly. For domain knowledge or workflows that are only relevant sometimes, use skills instead." Also: "Keep it concise. For each line, ask: 'Would removing this cause Claude to make mistakes?' If not, cut it. Bloated CLAUDE.md files cause Claude to ignore your actual instructions!" — [Best practices](https://code.claude.com/docs/en/best-practices)
- [OFFICIAL] Include: Bash commands Claude can't guess, non-default code style, testing instructions, repo etiquette, project-specific architectural decisions, environment quirks, gotchas. Exclude: anything derivable from code, standard conventions, detailed API docs (link instead), frequently changing info, long tutorials, file-by-file descriptions, "write clean code"-type platitudes. — [Best practices](https://code.claude.com/docs/en/best-practices)
- [OFFICIAL] "**Size**: target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence." Imports via `@path` "help you organize a long file but don't reduce its context cost". Use path-scoped `.claude/rules/` for instructions that matter only for part of the codebase. — [Memory](https://code.claude.com/docs/en/memory); "Aim to keep CLAUDE.md under 200 lines by including only essentials." — [Costs](https://code.claude.com/docs/en/costs)
- [OFFICIAL] Emphasis: "If Claude keeps skipping one instruction, add emphasis such as 'IMPORTANT' to that line alone. If you emphasize many lines, none of them stands out." Also: "Treat CLAUDE.md like code: review it when things go wrong, prune it regularly". — [Best practices](https://code.claude.com/docs/en/best-practices)
- [OFFICIAL] Hierarchy and load order: managed policy → user `~/.claude/CLAUDE.md` → project `./CLAUDE.md` or `./.claude/CLAUDE.md` → local `./CLAUDE.local.md`. Files in parent directories load at launch, files in subdirectories load on demand, and all are concatenated rather than overriding each other. Imports go at most four hops deep. HTML block comments are stripped before injection. — [Memory](https://code.claude.com/docs/en/memory)
- [OFFICIAL] "CLAUDE.md content is delivered as a user message after the system prompt… there's no guarantee of strict compliance". For must-run actions, use hooks: "Unlike CLAUDE.md instructions which are advisory, hooks are deterministic and guarantee the action happens." — [Memory](https://code.claude.com/docs/en/memory); [Best practices](https://code.claude.com/docs/en/best-practices)

**Auto memory**
- [OFFICIAL] Auto memory is stored at `~/.claude/projects/<project>/memory/` with a `MEMORY.md` index. "The first 200 lines of `MEMORY.md`, or the first 25KB, whichever comes first, are loaded at the start of every conversation." Topic files are read on demand. Subagents can have their own memory via the `memory` field. — [Memory](https://code.claude.com/docs/en/memory)

**Token-usage tips (Claude Code)**
- [OFFICIAL] The cost page lists these strategies: clear between tasks; custom compaction instructions; choose the right model ("Sonnet handles most coding tasks well and costs less than Opus. Reserve Opus for complex architectural decisions"; `model: haiku` for simple subagent tasks); reduce MCP overhead (prefer CLI tools); code-intelligence plugins; preprocess with hooks (e.g. filter test output to failures); move CLAUDE.md workflows to skills; lower effort/thinking for simple tasks; "Delegate verbose operations to subagents"; write specific prompts. — [Costs](https://code.claude.com/docs/en/costs)
- [OFFICIAL] Why usage climbs in long sessions: full history is resent each request; cache misses after a break (1-hour TTL on subscription, 5 minutes on API by default); "every subagent, and every agent a dynamic workflow spawns, sends its own requests on top of the main conversation's". — [Costs](https://code.claude.com/docs/en/costs)
- [OFFICIAL] "For Claude Code, we restrict tool responses to 25,000 tokens by default." — [Writing effective tools for agents (Sep 11, 2025)](https://www.anthropic.com/engineering/writing-tools-for-agents)

**API-level "context editing" (Claude Developer Platform, not a Claude Code setting)**
- [OFFICIAL] Context editing "selectively clear[s] specific content from conversation history". Tool result clearing (`clear_tool_uses_20250919`) defaults: trigger 100,000 input tokens, keep the 3 most recent tool uses; it also supports `clear_at_least` and `exclude_tools`. Thinking-block clearing is `clear_thinking_20251015`. The beta header is `context-management-2025-06-27`. It combines with the memory tool so Claude can save information "before they're cleared". Anthropic now "recommends server-side compaction over SDK compaction" (`compact_20260112`). — [Context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing)

### Inferences
- In a coordinator-only design, the coordinator's context grows mainly from subagent summaries and from its own planning. The docs' warning that many detailed subagent results "can consume significant context" implies the coordinator should ask for compact, structured returns, and should write durable state (plans, decisions) to files that survive compaction. CLAUDE.md, the plan-mode plan and auto memory are re-injected after compaction; ad-hoc conversation instructions are not.
- With 1M-context models auto-compacting near 967K, quality degradation from "context rot" (section 3) can set in long before compaction. That is a reason to `/clear` or lower `/autocompact` proactively instead of relying on the default threshold.

### Gaps
- I found no official numeric guidance on the context fill level at which to `/clear` or `/compact` (e.g. "at 50%"). The docs only say "between unrelated tasks" and "compact earlier" via `/autocompact`.
- I did not fetch the "How Claude Code works" page section "When context fills up". Its details on compaction internals may add nuance.

## 3. Anthropic Engineering blog: context engineering, multi-agent research system, best practices, long-running harnesses, tool design

### Takeaway
The engineering blog gives the theory behind the docs. Context is a finite "attention budget" subject to "context rot". The three long-horizon techniques are compaction, structured note-taking, and sub-agents returning condensed summaries of about 1–2K tokens. Orchestrator-worker multi-agent systems outperform single agents on broad, parallelizable research but use about 15× chat tokens and fit poorly with most coding tasks. Long-running coding work should run across fresh sessions bridged by a progress file, a JSON feature list and git commits.

### Cited Findings

**"Effective context engineering for AI agents" (published Sep 29, 2025)**
- [OFFICIAL] "Context engineering refers to the set of strategies for curating and maintaining the optimal set of tokens (information) during LLM inference". — [Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- [OFFICIAL] Context rot: "As the number of tokens in the context window increases, the model's ability to accurately recall information from that context decreases". LLMs have an "attention budget". — [Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- [OFFICIAL] "Good context engineering means finding the smallest possible set of high-signal tokens that maximize the likelihood of some desired outcome". — [Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- [OFFICIAL] System prompts at "the right altitude": "specific enough to guide behavior effectively, yet flexible enough to provide the model with strong heuristics". — [Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- [OFFICIAL] Just-in-time retrieval: agents "maintain lightweight identifiers and use these references to dynamically load data into context at runtime". Claude Code is hybrid: "CLAUDE.md files are naively dropped into context up front, while primitives like glob and grep allow it to navigate its environment and retrieve files just-in-time". — [Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- [OFFICIAL] Compaction in Claude Code: the model "preserve[s] architectural decisions, unresolved bugs, and implementation details" while discarding redundant tool outputs, then continues with "compressed context plus the five most recently accessed files". Tuning advice: "maximize recall… then iterate to improve precision". Warning: "Overly aggressive compaction can result in the loss of subtle but critical context whose importance only becomes apparent later". "One of the safest lightest touch forms of compaction is tool result clearing". — [Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- [OFFICIAL] Structured note-taking: "The agent regularly writes notes persisted to memory outside of the context window. These notes get pulled back into the context window at later times". [EXAMPLE] Examples given: a Claude Code to-do list, a NOTES.md file, and Claude playing Pokémon while tracking progress across thousands of steps. A memory tool was released with Sonnet 4.5. — [Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- [OFFICIAL] Sub-agent architectures: "Each subagent might explore extensively, using tens of thousands of tokens or more, but returns only a condensed, distilled summary of its work (often 1,000-2,000 tokens)". This achieves "clear separation of concerns": "the detailed search context remains isolated within sub-agents, while the lead agent focuses on synthesizing and analyzing the results." — [Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- [OFFICIAL] Which technique when: "Compaction maintains conversational flow for tasks requiring extensive back-and-forth; Note-taking excels for iterative development with clear milestones; Multi-agent architectures handle complex research and analysis where parallel exploration pays dividends". — [Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- [OFFICIAL] Tools: "If a human engineer can't definitively say which tool should be used in a given situation, an AI agent can't be expected to do better". — [Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)

**"How we built our multi-agent research system" (published Jun 13, 2025)**
- [EXAMPLE] Architecture: orchestrator-worker; a "lead agent coordinates the process while delegating to specialized subagents". — [Multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)
- [EXAMPLE] Performance: an Opus 4 lead with Sonnet 4 subagents "outperformed single-agent Claude Opus 4 by 90.2%" on Anthropic's internal research eval. — [Multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)
- [EXAMPLE] Tokens: "agents typically use about 4× more tokens than chat interactions, and multi-agent systems use about 15× more tokens than chats". "token usage by itself explains 80% of the variance" in performance on their BrowseComp analysis. — [Multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)
- [OFFICIAL] Economics: "Multi-agent systems require tasks where the value of the task is high enough to pay for the increased performance." — [Multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)
- [OFFICIAL] Poor fit: domains "that require all agents to share the same context or involve many dependencies between agents are not a good fit"; "most coding tasks involve fewer truly parallelizable tasks than research". — [Multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)
- [OFFICIAL] Delegation brief: "Each subagent needs an objective, an output format, guidance on the tools and sources to use, and clear task boundaries". [EXAMPLE] The vague instruction "research the semiconductor shortage" caused subagents to duplicate work (two explored 2025 supply chains while another covered the 2021 automotive crisis) "without clear labor division". — [Multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)
- [OFFICIAL] Scale effort to complexity: "Simple fact-finding requires just 1 agent with 3-10 tool calls, direct comparisons might need 2-4 subagents with 10-15 calls each", and complex research uses "10+ subagents with clearly divided responsibilities". — [Multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)
- [EXAMPLE] Parallelism: the "lead agent spins up 3-5 subagents in parallel", and "subagents use 3+ tools in parallel. These changes cut research time by up to 90%". — [Multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)
- [EXAMPLE] Memory and handoff: because "if the context window exceeds 200,000 tokens it will be truncated", the lead saves "its plan to Memory to persist the context". When approaching limits, the system can "spawn fresh subagents with clean contexts while maintaining continuity through careful handoffs". Agents "summarize completed phases and store essential information in an external memory before proceeding". — [Multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)
- [OFFICIAL] Filesystem outputs: "Subagents call tools to store their work in external systems, then pass lightweight references back to the coordinator. This prevents information loss during multi-stage processing" (the "game of telephone" problem) and reduces token overhead. — [Multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)
- [EXAMPLE] Limitations: "lead agents execute subagents synchronously, waiting for each set of subagents to complete before proceeding", which creates bottlenecks. "Agents are stateful and errors compound", so resume from checkpoints rather than restarting. — [Multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)
- [OFFICIAL] Other principles: "think like your agents" (simulate them); let Claude improve prompts and tools ([EXAMPLE] a tool-testing agent produced "a 40% decrease in task completion time"); start wide then narrow; use extended thinking as a scratchpad; start evals with about 20 cases; use LLM-as-judge plus human testing. — [Multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)

**"Effective harnesses for long-running agents" (published Nov 26, 2025)**
- [OFFICIAL] Problem: "Each new session begins with no memory of what came before". Also: "compaction isn't sufficient"; even "Opus 4.5 running on the Claude Agent SDK" falls short of a production-quality web app with compaction alone. — [Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)
- [OFFICIAL] Failure modes: (1) the agent "tended to try to do too much at once—essentially to attempt to one-shot the app"; (2) "A later agent instance would look around, see that progress had been made, and declare the job done." — [Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)
- [EXAMPLE] Two-part solution. An **initializer agent** (first session) creates `init.sh`, a `claude-progress.txt` progress log, a feature list, and an initial git commit. A **coding agent** (every later session) makes incremental progress and leaves structured updates. "The system prompt, set of tools, and overall agent harness was otherwise identical"; only the initial user prompt differs. — [Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)
- [EXAMPLE] Feature list as JSON (over 200 features, all initially `"passes": false`), e.g. `{"category": "functional", "description": "New chat button creates a fresh conversation", "steps": [...], "passes": false}`. JSON is used because "the model is less likely to inappropriately change or overwrite JSON files compared to Markdown files". The instructions say: "It is unacceptable to remove or edit tests because this could lead to missing or buggy functionality." — [Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)
- [OFFICIAL] "the next iteration of the coding agent was then asked to work on only one feature at a time." — [Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)
- [OFFICIAL] "Clean state" means "the kind of code that would be appropriate for merging to a main branch: there are no major bugs, the code is orderly and well-documented, and in general, a developer could easily begin work on a new feature without first having to clean up an unrelated mess." — [Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)
- [OFFICIAL] Session-start routine: "Run `pwd` to see the directory you're working in." Then: "Read the git logs and progress files to get up to speed on what was recently worked on." Then: "Read the features list file and choose the highest-priority feature that's not yet done to work on." After that, run `init.sh` and a basic end-to-end check before new work. Git is used "to revert bad code changes and recover working states of the code base". — [Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)
- [EXAMPLE] End-to-end testing with browser automation (Puppeteer MCP) "dramatically improv[ed]" bug detection. — [Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)
- [OFFICIAL, open question] It is unresolved whether "a single, general-purpose coding agent performs best across contexts, or if better performance can be achieved through a multi-agent architecture" (e.g. testing, QA or cleanup agents). — [Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)

**"Writing effective tools for agents" (published Sep 11, 2025)**
- [OFFICIAL] "Optimizing the quality of context is important. But so is optimizing the *quantity* of context returned back to agents in tool responses." Anthropic recommends "some combination of pagination, range selection, filtering, and/or truncation with sensible default parameter values". — [Writing tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents)

## 4. Concrete recommendations: fresh context vs. compact; handoff notes / progress files; task size per agent; number of parallel agents; cost trade-offs

### Takeaway
Anthropic's concrete rules: start fresh (`/clear` or a new session) between unrelated tasks, after two failed corrections, and before implementing from a written spec. Compact with explicit focus only when continuity is valuable. Hand off through files: a spec or plan, a progress log, a JSON feature list, git history. Give each agent one self-contained deliverable (one feature, function, test file or review). Run about 3–5 parallel workers. Expect large token multipliers: about 4× for agents, about 15× for multi-agent versus chat, and about 7× for agent teams in plan mode.

### Cited Findings

**Fresh context vs. compact**
- [OFFICIAL] "If you've corrected Claude more than twice on the same issue in one session, the context is cluttered with failed approaches. Run `/clear` and start fresh with a more specific prompt that incorporates what you learned. A clean session with a better prompt almost always outperforms a long session with accumulated corrections." — [Best practices](https://code.claude.com/docs/en/best-practices)
- [OFFICIAL] Failure patterns: "The kitchen sink session… Fix: `/clear` between unrelated tasks." Also: "The infinite exploration… Fix: Scope investigations narrowly or use subagents". — [Best practices](https://code.claude.com/docs/en/best-practices)
- [OFFICIAL] Spec handoff: after an interview-generated `SPEC.md`, "start a fresh session to execute it. The new session has clean context focused entirely on implementation, and you have a written spec to reference." "The most useful specs are self-contained: they name the files and interfaces involved, state what is out of scope, and end with an end-to-end verification step". — [Best practices](https://code.claude.com/docs/en/best-practices)
- [OFFICIAL] "A fresh context improves code review since Claude won't be biased toward code it just wrote." The Writer/Reviewer pattern uses two sessions. — [Best practices](https://code.claude.com/docs/en/best-practices)
- [OFFICIAL] Compact "with a focus… before starting a long new task. The summary keeps what you choose instead of what the automatic pass guesses is important." — [Context window](https://code.claude.com/docs/en/context-window)
- [OFFICIAL] Counterpoint: "Sometimes you *should* let context accumulate because you're deep in one complex problem and the history is valuable." — [Best practices](https://code.claude.com/docs/en/best-practices)
- [OFFICIAL] Compaction is lossy: "Overly aggressive compaction can result in the loss of subtle but critical context". — [Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents). Also, compaction alone "isn't sufficient" for multi-session builds — [Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)

**Handoff notes / progress files**
- [EXAMPLE→pattern] Harness pattern: `claude-progress.txt` (log of what each session did), a JSON feature list with a `passes` flag, `init.sh`, and descriptive git commits. Each session starts with `pwd`, reads the git log and progress file, reads the feature list, picks the top unfinished feature, runs basic tests, and ends in a "clean state". — [Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)
- [OFFICIAL] Note-taking (to-do list, NOTES.md) "excels for iterative development with clear milestones". — [Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- [EXAMPLE] The research lead saves its plan to memory before the 200K truncation and hands off to fresh subagents "through careful handoffs". Subagents write outputs to the filesystem and pass references. — [Multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)
- [OFFICIAL] Claude Code mechanics that persist across compaction or clear: CLAUDE.md, auto memory (`MEMORY.md` index, 200 lines/25KB), the plan-mode plan file, and subagent `memory`. — [Context window](https://code.claude.com/docs/en/context-window); [Memory](https://code.claude.com/docs/en/memory)
- [OFFICIAL] Teammate spawn prompts must carry task context because teammates "don't inherit the lead's conversation history". The example spawn prompt names a path, a focus, tech details (JWT in httpOnly cookies), and the output ("Report any issues with severity ratings"). — [Agent teams](https://code.claude.com/docs/en/agent-teams)

**Task size per agent**
- [OFFICIAL] Agent teams: "**Too small**: coordination overhead exceeds the benefit. **Too large**: teammates work too long without check-ins, increasing risk of wasted effort. **Just right**: self-contained units that produce a clear deliverable, such as a function, a test file, or a review." Also: "Having 5-6 tasks per teammate keeps everyone productive and lets the lead reassign work if someone gets stuck." — [Agent teams](https://code.claude.com/docs/en/agent-teams)
- [OFFICIAL] "Keep team tasks small and self-contained to limit per-teammate token usage." — [Costs](https://code.claude.com/docs/en/costs)
- [OFFICIAL] Long-running coding: "work on only one feature at a time". — [Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)
- [OFFICIAL] Research effort scaling: 1 agent with 3–10 tool calls; 2–4 subagents with 10–15 calls each; 10+ subagents for complex work. — [Multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)
- [OFFICIAL] Avoid file conflicts: "Two teammates editing the same file leads to overwrites. Break the work so each teammate owns a different set of files." — [Agent teams](https://code.claude.com/docs/en/agent-teams). Worktree isolation is available via `isolation: worktree` — [Subagents](https://code.claude.com/docs/en/sub-agents)
- [OFFICIAL] Fan-out: "Refine your prompt based on what goes wrong with the first 2-3 files, then run on the full set." — [Best practices](https://code.claude.com/docs/en/best-practices)

**How many parallel agents**
- [OFFICIAL] "Start with 3-5 teammates for most workflows… If you have 15 independent tasks, 3 teammates is a good starting point… Three focused teammates often outperform five scattered ones." Constraints: token costs scale linearly, coordination overhead increases, and returns diminish. — [Agent teams](https://code.claude.com/docs/en/agent-teams)
- [EXAMPLE] The research system ran 3–5 subagents in parallel. — [Multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)
- [OFFICIAL] Hard limits: 20 concurrent subagents by default; nesting up to 3 levels. `/batch` uses 5–30 worktree subagents. — [Subagents](https://code.claude.com/docs/en/sub-agents); [Best practices](https://code.claude.com/docs/en/best-practices)

**Cost trade-offs**
- [EXAMPLE] About 4× tokens for agents and about 15× for multi-agent systems versus chat. Token usage explains 80% of performance variance. — [Multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)
- [OFFICIAL] "Agent teams use approximately 7x more tokens than standard sessions when teammates run in plan mode". — [Costs](https://code.claude.com/docs/en/costs). Teams use "significantly more tokens than a single session… For routine tasks, a single session is more cost-effective." — [Agent teams](https://code.claude.com/docs/en/agent-teams)
- [OFFICIAL] Use Sonnet for teammates; keep spawn prompts focused; shut teammates down when done. — [Costs](https://code.claude.com/docs/en/costs)
- [OFFICIAL] The enterprise average is about $13 per developer per active day and $150–250 per developer per month, with 90% of users below $30 per active day. — [Costs](https://code.claude.com/docs/en/costs)
- [OFFICIAL] Forks reuse the parent's prompt cache, making them "cheaper than spawning a fresh subagent for tasks that need the same context". In-process teammate caches default to a 5-minute TTL (`subagentPromptCacheTtl` can set 1h). — [Subagents](https://code.claude.com/docs/en/sub-agents); [Agent teams](https://code.claude.com/docs/en/agent-teams)

### Inferences
- **For a "main agent only coordinates" setup**, Anthropic's guidance supports: keeping the coordinator's context lean; delegating research, verbose operations, parallel independent work and independent review; requiring briefs with objective, output format, tools and sources, and boundaries; requiring short (about 1–2K token) summaries or file references back; persisting plans and progress in files and git; and keeping about 3–5 workers in parallel on disjoint files.
- The same guidance **warns against** delegating everything indiscriminately. Tightly coupled, iterative, same-file or quick tasks are better done in one context. Most coding is less parallelizable than research. Every delegation adds startup cost (CLAUDE.md copy, re-gathering context) and multiplies tokens (about 4–15×). A reasonable synthesis is "coordinate by default, but do quick or coupled steps inline, or use a fork."
- Anthropic's own observation that leads sometimes "start implementing tasks itself instead of waiting" shows that coordinator discipline needs an explicit instruction. CLAUDE.md is advisory, so hooks or tool restrictions (e.g. `tools`/`disallowedTools` in an `--agent` main-session definition) are the deterministic way to enforce it.

### Gaps
- I found no official Anthropic guidance specifically endorsing a *pure* coordinator main agent for Claude Code coding work. The closest analogues are the research orchestrator (blog) and the agent-team lead (experimental docs).
- I found no official template for a Claude Code "handoff note" beyond the harness article's `claude-progress.txt` and feature-list JSON and the SPEC.md guidance. The exact internal layout of `claude-progress.txt` was not shown in the retrieved content.
- I found no official metric for when to `/clear` based on context percentage, and no Claude-Code-specific measurement of the subagent token multiplier (the 15× is from the 2025 research system; the 7× is for agent teams in plan mode).
